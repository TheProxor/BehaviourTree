# Базовые узлы

Описание соответствует реализации этого пакета.

Каждый вызов UpdateNode возвращает Running (работа продолжается), Success (успех) или Failure (неудача). Disabled — состояние ещё не запущенного/сброшенного узла. Первый вызов запускает OnStart, затем вызывается OnUpdate. При завершении вызывается OnStop. При новом запуске OnStart вызывается снова.

## Sequencer

Выполняет детей по порядку. Running удерживает текущий шаг; Success переводит к следующему. Несколько мгновенно завершившихся шагов могут выполниться за один тик.

В этой реализации AbortOnAnyChildFailure по умолчанию выключен: обычный Failure пропускается и последовательность продолжается. Если флаг включён, Failure завершает секвенсор. Failure от AbortableNode с AbortType LowerPriority или Both также завершает секвенсор. В конце возвращается Success.

Пример: подойти → прицелиться → выстрелить.

## Selector

Пробует детей по порядку: Failure — перейти к следующему; Success — завершиться успешно; Running — продолжать этого ребёнка на следующем тике. Если все варианты провалились, возвращает Failure.

Ранее расположенные дети приоритетнее. Условия с режимами OnValueChange/OnResultChange могут через события вернуть селектор к более приоритетной ветке; реакция на прерывание задаётся AbortType. Это не повторная проверка всех условий каждый кадр.

Пример: атаковать видимого врага → искать врага → патрулировать.

## Parallel

Обновляет несколько детей за один тик дерева обычными последовательными вызовами, без дополнительных потоков.

- FinishType None: остаётся Running, пока хотя бы один ребёнок возвращает Running; иначе Success.
- FinishType Immediate: успех первого ребёнка завершает Parallel и прерывает оставшиеся работающие ветки.
- AbortWhenAnyFailure = true: первый Failure завершает Parallel с Failure и прерывает работающие ветки.
- AbortWhenAnyFailure = false: провалившиеся дети обновляются повторно, пока сам Parallel продолжает работу. Успешные дети больше не обновляются. Если ни один ребёнок не вернул Running, Parallel завершается успешно даже при наличии Failure.

Пример: одновременно двигаться и стрелять. Чтобы прекратить стрельбу по прибытии, движение должно быть первым ребёнком, а FinishType — Immediate. Циклическую стрельбу можно завернуть в Loop.

## RandomSelector

Выбирает одного случайного ребёнка при старте и возвращает его состояние. После Failure не перебирает остальные варианты.

## Condition

Декоратор с одним ребёнком. Истинное условие разрешает его выполнение, ложное возвращает Failure. Invert переворачивает результат. Enabled = false пропускает проверку и разрешает выполнение ребёнка.

Начальное значение запоминается при OnStart. Для обновления значения реализация конкретного условия должна вызвать OnValueChanged. Режим ConditionType также определяет подписку родительского селектора на события.

## Wait, Cooldown, Chance, Loop

- Wait выбирает время из DurationMinMax, возвращает Running до его истечения, затем выполняет ребёнка. Если ребёнка нет, возвращает Success.
- Cooldown разрешает ребёнка после истечения задержки. Во время задержки возвращает Failure. OnSuccess запускает задержку после успешного завершения ребёнка. Always запускает/перезапускает её при каждом OnStop, в том числе после отказа во время cooldown: частые повторные попытки могут отодвигать доступность.
- Chance один раз при старте выбирает, разрешать ли ребёнка, с вероятностью Value. При отказе возвращает Failure.
- Loop считает успешные завершения ребёнка. Достигнув LoopCount, возвращает Success. Failure ребёнка не завершает цикл и не увеличивает счётчик. LoopCount = 0 фактически означает бесконечное повторение.

## Root, Action, SubTree и blackboard

- Root — вход в дерево, возвращает результат своего ребёнка; без ребёнка возвращает Failure.
- Action — конечная операция. Сам узел определяет, сколько работать и каким результатом закончить.
- SubTree — отдельный ассет дерева, клонируемый при привязке контекста. Поддерживает переопределение значений blackboard.
- NestedRoot/NestedCall позволяют определить и вызвать именованную ветку внутри одного дерева.
- Blackboard хранит общие типизированные значения. Set записывает значение; ConditionKey использует их для проверки.

Декораторы обычно имеют одного ребёнка, композитные узлы — несколько. Связывайте ветки в редакторе; узлы, требующие ребёнка, не должны оставаться без подключённой ветки.
